Ownership save semantics
------------------------
The user revised the ownership behavior: hidden PDF drafts are discarded on save, not
on hide; saved PDF records and files remain. Hidden contact drafts need not be retained.
A successful property save removes saved hidden-side contact links without deleting people.
New-property listing handoff is not a database commit. Direct listing saves still use the
committed property ownership. General listing PDF validation parity remains separate.

Residential and Commercial property saves now save the visible ownership side in the same
transaction, clear hidden contact drafts, and clean hidden unsaved PDFs after a successful
save. Existing listing updates still use ListingUpdatedMessage. A listing save under a new
property transfers its draft to the property editor; it does not commit it to the database.
Residential listing save flags, hidden-contact state, and PDF editor tracking were removed from
the listing model. PDF cleanup retries remain with the owning editor. Commercial listing models
also do not carry that editor bookkeeping. Runtime verification remains outstanding, particularly
for cleanup failures, repeated handoffs, and save/discard behavior.

Known findings and follow-up concerns
-------------------------------------
Commercials:
- Listing duplication remains unfinished by user decision, as noted above.
- Listing lessor/broker associations now support direct and parent-property persistence; runtime
  verification remains outstanding.
- Search beyond name matching is deferred.
- After search deletion commits, failed attachment cleanup is reported but has no automatic

Shared / Residentials (separate from the current Commercials slices):
- Shared location-master SQL queries interpolate names. Names with SQL-special characters
  can fail lookup or produce unexpected matching. Parameterize in a separately approved
  shared-infrastructure change; this affects Residentials as well as Commercials.
- Residentials area filtering converts stored text after comma removal; full-width digits
  or comma-decimal values may be interpreted incorrectly. Fixing numeric representation
  and search behavior needs separate approval.
- Residentials association recovery and cleanup safeguards were implemented in the logged
  work, but their save-failure, retry, ownership-switching, and parent/child behavior are
  still runtime-unverified.
- Residentials ownership navigation separates draft and committed values, initializes
  search-opened editors, restores visibility on discard, and prunes hidden history. Direct
  listing saves use database ownership; runtime verification remains outstanding.
- Residentials previously had an invalid-data recovery concern involving a saved listing
  with multiple main PDFs. The new ownership save gates change that path, but its recovery
  behavior remains runtime-unverified; broader listing PDF validation remains separate.
