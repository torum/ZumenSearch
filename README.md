# ZumenSearch
不動産図面管理システム - 物件情報と図面（マイソク・ファクトシート）PDFをデジタル管理。
（Under developement）

### 目的

1. 図面をローカル環境でデジタル管理し、自社物件だけではなく流通する他社物件の募集図面を含め、条件検索、物件検索、貸主検索、宅建業者検索などを可能にする。
3. 将来的な不動産データ標準化に際し、API・プロトコルのテストクライアント及びその後のリファレンス実装とする。
4. 不動産業務システムをモダンなWinUIで開発できることの実証デモ。

### 背景

1. 不動産の募集・販売図面は従来の紙からPDFベースで流通・取得することが多くなった。しかし、それら他社もの含めた流通情報を図面PDF込みでデジタル整理するツールの存在が欠けている。もともと日本の不動産業務に関するツールはアプリ・ストアを見てもまったく存在していない。

2. 現在のところ、[米国のRESO](https://note.com/torum/n/n7460f48b170f)などと異なり、日本の不動産物件データのドキュメントやAPI・プロトコルの仕様標準化の動きは無い。しかし将来的に仕様を検討する際に相互運用性の検証などの為にクライアント側とサーバー側のそれぞれテスト用のシステムが必要。仕様が策定された際には「リファレンス実装」としても有用となる。

3. 日本では、不動産業の本来業務に関するソフトウェア・システムは少数の企業が提供する商用業務基幹アプリケーションに限られる。それも、使い勝手の悪いウェブベースのクラウド系不動産業務システムか、または古いWindows Formsという数世代前のデスクトップUIフレームワークをベースに作られた不動産業務システムとなる。ウェブベースの業務システムはネイティブのアプリケーションと比較して、機能性・パフォーマンス・OS準拠のUI/UX・セキュリティ等々で劣る。デスクトップの業務システムはどれももはや更新されることの無い古いWindows Formsのままで、WPFへ移行もされてこず、　現在のマイクロソフト公式フラッグシップUIフレームワークであるWinUIというモダンなUIフレームワークで再構築されてもいない。

### 技術的設計方針

* Windows App SDK（WinUI3）を使ったモダンUI。
* MVVM (Model-View-ViewModel) アーキテクチャ設計パターンを使い、XAMLのUIレイヤーとドメインロジックの分離・疎結合化。
* Generic Hostを使用してインフラストラクチャーを構成し、サービス管理とDependency Injection（依存関係注入）を行う。
* RDBMSとしてはSQLiteを利用し、将来的にWebAPIでサーバーをプライマリとする際はローカルキャシュとして扱う。
* DDD (Domain-Driven Design：ドメイン駆動設計) を現実的な限り適用。
* Native AOTによるネイティブコンパイルを可能とし、起動速度の高速化とメモリフットプリントの最小化。単体実行形式に加え、MSIX等のストア公開可能なパッケージ形式にも対応。
