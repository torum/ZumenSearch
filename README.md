# ZumenSearch
不動産図面管理システム - 物件情報と図面（マイソク・ファクトシート）PDFをデジタル管理。
（Under developement）

### 目的

1. 物件情報を募集・販売図面と共にローカル環境でデジタル管理し、自社物件だけではなく流通する他社物件の募集・販売図面を含め、物件検索、条件検索、貸主検索、宅建業者検索などを可能にする。
2. 実務に利用可能なレベルを目標とし、不動産業務システムをモダンなWinUIで開発・実装できることの実証デモとすることを最低限クリアすべき目的とする。
3. 将来的な不動産データ標準化を視野に入れ、API・プロトコル相互運用性のテスト用クライアント及びリファレンス実装となることを想定する。

### 背景

1. 不動産の募集・販売図面は従来の紙（マイソク・ファクトシート）からPDFファイル形式で流通・取得することが多くなった。しかし、それら他社もの含めた流通情報を図面（PDF）込みでデジタル整理するツールの存在が欠けている。もともと日本の不動産業務に関するツールはアプリストアを見てもまったく存在していない。

2. 現在のところ、[米国のRESO](https://note.com/torum/n/n7460f48b170f)などと異なり、日本の不動産物件データのドキュメントやAPI・プロトコルの仕様標準化の動きは無い。しかし将来的に仕様を検討する際に相互運用性の検証などの為にクライアント側とサーバー側のそれぞれテスト用のシステムが必要となる。仕様が策定された際には「リファレンス実装」としても活用できる。

3. 日本では、不動産業の本来業務に関するソフトウェア・システムは少数の企業が提供する商用業務基幹アプリケーションに限られる。それも、使い勝手の悪いウェブベースのクラウド系不動産業務システムか、または古いWindows Formsという数世代前のデスクトップUIフレームワークをベースに作られた不動産業務システムのどちらかとなる。クラウドのウェブベースの業務システムは利便性もあるが、ネイティブのアプリケーションと比較すると機能性・パフォーマンス・OS準拠のUI/UX・セキュリティ等々で劣ったもとのなる。その一方、既存のデスクトップのローカル業務システムはどれも古いWindows Formsのままで、WPFへ移行もされてこず、現在のマイクロソフト公式フラッグシップUIフレームワークであるWinUIというモダンなUIフレームワークへ移行や再構築がされていない。

### 技術的設計方針

* Windows App SDK（WinUI3）を使ったモダンUI。
* MVVM (Model-View-ViewModel) アーキテクチャ設計パターンを使い、XAMLのUIレイヤーとドメインロジックの分離・疎結合化。
* Generic Hostを使用してインフラストラクチャーを構成し、ライフサイクル管理とDependency Injection（依存関係注入）を行う。
* RDBMSとしてはSQLiteを利用し、将来的にWebAPIを介してのクライアント・サーバー3層構成に移行する際はローカルキャシュとして扱う。
* DDD (Domain-Driven Design：ドメイン駆動設計) を現実的な限り適用。
* Native AOTによるネイティブコンパイルを可能とし、起動速度の高速化とメモリフットプリントの最小化を図る。また、単体実行形式に加え、MSIX等のストア公開可能なパッケージ形式にも対応する。

### プロジェクト構成

`Src` 以下は現状のところ単一の WinUI プロジェクト。業務機能ごとのモデル・ViewModel・画面は `Features`、共通モデル・ダイアログ・ヘルパーは `Shared`、データアクセス・設定・DI の補助は `Infrastructure`、シェルと UI サービスは `Presentation` に配置する。`Assets` と `Data` は実行時のパスを維持するため既定の場所に置く。
注：既存の名前空間は互換性のため変更していない。フォルダー名と名前空間は必ずしも一致しない。名前空間を変更する場合は XAML の `x:Class`・名前空間参照やナビゲーションに使う名前も併せて確認する。
