Sale Residentials: early implementation snapshot

Draft — incomplete implementation, not a finalized schema. This snapshot records the current editor and fresh SQLite schema as of 2026-11-22. Some mappings below describe intended save columns, not working persistence; see the caveats before using them.

Japanese labels are from the current UI. Shared concepts are described in the common property specification, but this feature does not currently implement all shared inputs or use all shared columns in the same way.

Implementation caveats

  • Property save/load mismatch: the fresh schema defines property_kind, but the property upsert and lookup query reference property_type. Against that schema these operations cannot complete normally; the upsert is transactional.
  • Address load: the property lookup selects location column names without the loc... aliases later used to read them; the latitude/longitude reader names also differ from the selected names. This is a separate load-path mismatch.
  • Build date: the date picker has no active binding. The view model uses a 1900-01-01 fallback when its value is unset.
  • Listing save: SQL expects price, management fee, reserve, ownership, occupancy and delivery parameters, but their parameter bindings and corresponding domain fields are commented out. The listing save path is incomplete.
  • Common property data: there are no location or transportation inputs on the current basic page. The property upsert writes address components from the model but omits the shared identifier columns, postal code, coordinates and transportation; it does not establish that these data are editable in this feature.
