Rent Commercials: pre-rewrite specification

Draft — pre-rewrite implementation snapshot, not an approved schema. The existing UI and fresh SQLite schema are recorded as of 2026-11-22 to inform reconstruction. This is not a requirement to retain current defects or design choices.

Japanese labels come from the current editors; descriptions are in English. A schema column alone does not establish that an input is saved or reloaded. Shared property fields and person fields are documented separately.

Media tables also store record IDs and owner IDs; files themselves are stored outside the database. Listing media tables have partial unique indexes allowing at most one main picture and one main PDF per listing; their save paths also check that constraint. Property PDF records additionally have creation/update timestamps.

Schema and persistence notes

  • Property identifiers: the commercial property editor accepts 不動産番号 and 特定コード, and load reads properties.fudousan_id and properties.fudousan_id_additional_code, but its property upsert omits them. Changes to these fields are not written by that save path. The property upsert also omits properties.location_postal_code.
  • Listing identifier: rent_commercial_units.fudousan_id_additional_code exists in the schema but has no listing editor input and is omitted from the listing upsert and active listing load. The loaded property identifier is a separate value from properties.fudousan_id.
  • Schema-only parking: rent_commercial_units.parking_available has no listing editor input and is omitted from the listing upsert and active editor load.
  • Property rent_commercials.property_id links to the shared property row; rent_commercials.created_at and rent_commercials.updated_at are timestamps. Listing rent_commercial_units.listing_id, rent_commercial_units.property_id, rent_commercial_units.is_property_unit_ownership, rent_commercial_units.created_at and rent_commercial_units.updated_at are identifiers, parent context or timestamps, not separate listing inputs.
  • SQLite storage types are not uniform: for example, listing chinryou is NUMERIC while several other fee values are TEXT; nullable columns and default values should be reviewed in the schema rather than inferred from the UI.
  • The parking-free explanatory text on the property facilities page is display-only, not a separate stored input. Property- and unit-ownership modes can affect which details are saved; inspect the current save path when reconstructing that behavior.
